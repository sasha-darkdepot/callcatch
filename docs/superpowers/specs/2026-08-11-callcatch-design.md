# CallCatch — детект звонков и запись через Plaud

**Дата:** 2026-08-11
**Статус:** дизайн утверждён; прошёл discovery-ревью (coherence, feasibility,
design-lens, adversarial + кросс-модельный проход Codex/GPT-5.6), правки внесены

## Проблема

Приложение Plaud (десктоп, macOS) умеет авто-детектить звонки только для жёстко
зашитого списка приложений (zoom, teams, slack, webex, lark, браузеры).
Discord и WhatsApp его нативный монитор распознаёт, но отфильтровывает;
Telegram и Signal не распознаёт вообще. Правкой конфига это не расширяется
(список `supportMeetingAppKeysGlobal` зашит в код, `autoRecordApps` фильтруется
по нему).

Нужно: при начале звонка в Discord / Signal / Telegram / WhatsApp показывать
бабл внизу экрана с кнопкой «запустить запись», которая стартует запись в Plaud.

## Ключевые факты о Plaud (проверено по коду v1.3.7)

- Electron-приложение, bundle id `ai.plaud.desktop.plaud`.
- **Старт записи программно:** deep link `plaud://record?auto=1&user_id=<id>`
  (механизм, которым пользуется web.plaud.ai). Проверки на стороне Plaud:
  запись не идёт; `user_id` совпадает с id или id_hash залогиненного
  пользователя. При несовпадении Plaud показывает своё уведомление об ошибке.
- **Deep link — fire-and-forget с целым рядом ТИХИХ отказов** (проверено по
  коду `recordingService`): запрос молча игнорируется, если запись уже идёт;
  если `isRecordingAvailable == false` (профиль ещё не загружен — только
  показывается главное окно); если `recorderUnavailable`; если не удалось
  переключить workspace. **Холодный старт:** protocol-запрос обрабатывается
  сразу после `whenReady`, до сетевой загрузки профиля, и в этом окне
  отклоняется с reason `not_available` без повтора — то есть при незапущенном
  Plaud однократный deep link в общем случае запись НЕ запускает.
- **Подтверждение старта возможно по логам Plaud**
  (`~/Library/Application Support/Plaud/logs/log-*.log`): при успехе пишется
  `startRecording by scene success`, при отказе — `recording_start_rejected`
  с reason. Это единственный наблюдаемый канал результата deep link.
- `user_id` присутствует в логах **условно**: строки `userId` появляются при
  событиях аплоада, `user_id=` — в залогированных web deep link'ах; ротация
  логов — 14 дней. У неактивного пользователя логи могут не содержать id.
- **Программного стопа нет:** ни deep link, ни локального сервера, ни хоткея,
  ни пункта в tray-меню. Выход из приложения останавливает запись корректно,
  но показывает диалог подтверждения. Единственный путь — Accessibility-клик
  по кнопке стопа (эквивалент ручного клика, штатное сохранение и обработка).
  Кнопка стопа живёт в одной из трёх поверхностей (выбор делает сам Plaud):
  highlight-окно, mini-виджет или главное tray-окно.
- **Plaud — Electron:** accessibility-дерево web-контента не строится, пока
  assistive-клиент не выставит атрибут `AXManualAccessibility = true` на
  AX-элементе приложения. Без этого шага AX-обход видит окна без кнопок.
- Любой нераспознанный `plaud://` URL (без `auto`/`auth_code`) гарантированно
  вызывает `createOrFocusRecordingMainWindow` — надёжный способ поднять окно
  записи Plaud (используем `plaud://open` как fallback).

## Решение

Нативное menu bar приложение на Swift (AppKit + SwiftUI), без Dock-иконки
(LSUIElement). Рабочее название **CallCatch**.

### Компоненты

**1. MicMonitor — детектор звонков.**
CoreAudio Process Objects API (macOS 14.4+): системные события «процесс
начал/закончил использовать микрофон» (`kAudioHardwarePropertyProcessObjectList`,
`kAudioProcessPropertyIsRunningInput` + property listeners). Событийно, без
поллинга, разрешения не требуются.

Отслеживаются **4 логических приложения через 5 префиксов bundle id**
(у Electron-приложений звук идёт из helper-процессов вида `<bundle>.helper`,
поэтому матчинг по префиксу; WhatsApp — нативный, событие придёт от главного
процесса; если `kAudioProcessPropertyBundleID` пуст — fallback: PID →
`NSRunningApplication.bundleIdentifier`):

| Приложение | Префикс bundle id |
|---|---|
| Discord | `com.hnc.Discord` |
| Signal | `org.whispersystems.signal-desktop` |
| Telegram (macOS, обе версии) | `ru.keepcoder.Telegram` |
| Telegram Desktop | `org.telegram.desktop` |
| WhatsApp | `net.whatsapp.WhatsApp` |

Семантика: «приложение использует микрофон» == «идёт звонок». Ложные
срабатывания (голосовое сообщение в Telegram) допустимы для бабла;
про авто-режим см. ограничение в разделе Menu bar.

**Модель сессий:** активные звонки — множество (одновременно Discord и
Telegram — две сессии). События наружу: `callStarted(app)`, `callEnded(app)`.
Конец звонка — с дебаунсом 5 сек (переподключение/смена аудиоустройства не
считается концом). Запись, запущенная CallCatch, привязывается к
сессии-владельцу; `callEnded` другой сессии запись не трогает.

**2. PlaudController — управление Plaud.**
- `startRecording()` — **конечный автомат pending → confirmed / failed**,
  а не fire-and-forget:
  1. Отправить `plaud://record?auto=1&user_id=<id>` → состояние `pending`.
  2. Подтверждение — tail лога Plaud: `startRecording by scene success` →
     `confirmed`; `recording_start_rejected` → `failed` (с reason).
  3. Если Plaud не был запущен (холодный старт): повторять deep link с
     backoff каждые 3–5 сек до 60 сек до подтверждения. Повторы идемпотентны
     (при уже идущей записи Plaud игнорирует запрос).
  4. Внутренний флаг «запись идёт (наша)» ставится ТОЛЬКО по `confirmed`
     и привязывается к сессии звонка.
- `user_id`: при первом запуске автоматически извлекается из логов Plaud;
  кэшируется в настройках CallCatch. Если в логах нет (ротация 14 дней,
  неактивный пользователь) — в настройках инструкция восстановления:
  «при запущенном Plaud нажми Record на web.plaud.ai — свежий deep link с
  user_id попадёт в текущий лог» + кнопка «Найти снова».
- `stopRecording()`:
  1. Выставить `AXManualAccessibility = true` на AX-элементе приложения Plaud
     (обязательный первый шаг; повторять после перезапуска Plaud).
  2. AX-обход трёх поверхностей (highlight-окно, mini-виджет, главное окно),
     найти кнопку стопа, `AXPress`. Требует разрешения Accessibility
     (запрашивается при первом использовании).
  3. Fallback при любой неудаче: открыть `plaud://open` — Plaud гарантированно
     поднимет окно записи (надёжнее активации окон tray-приложения, у которого
     все окна могут быть скрыты) — пользователь жмёт стоп сам.
- Знание «идёт ли запись»: подтверждённый флаг (см. автомат) + перед показом
  бабла конца — AX-проверка наличия индикатора записи (уже после включения
  AXManualAccessibility). Если состояние неопределимо — бабл конца показываем.
  Запись, которую CallCatch не запускал (пользователь стартовал вручную),
  не трогаем: кнопку стопа не предлагаем, авто-действий не выполняем.

**3. BubbleWindow — бабл.**
Плавающая панель: NSPanel, non-activating, поверх всех окон,
`collectionBehavior = [.canJoinAllSpaces, .fullScreenAuxiliary]` (иначе бабл
не виден поверх полноэкранного звонка), `sharingType = .none` (бабл не попадает
в захват экрана при шаринге/записи — виден только пользователю). Внизу по
центру основного экрана. Панель non-activating — кнопки доступны только
мышью/трекпадом; это осознанное ограничение, клавиатурный/VoiceOver-эквивалент
всех действий — пункты меню в menu bar. Бабл показывается независимо от
Focus/DND (осознанное решение: пользователь уже в звонке, бабл относится
к текущей активности, а не отвлекает от неё).

Состояния:

- **Старт звонка:** «📞 Звонок в {приложение} — [Записать в Plaud] [✕]».
  Висит, пока идёт звонок, либо до закрытия. Если звонок закончился, а запись
  так и не запускалась — бабл скрывается, отложенный авто-старт отменяется.
- **Запуск записи** (после клика или авто-старта): «Запускаю запись…»
  (при незапущенном Plaud — «Запускаю Plaud…»). Висит до исхода автомата:
  `confirmed` → «🔴 Запись начата» → скрыть (2 сек);
  `failed`/таймаут → «⚠️ Запись не началась — [Открыть Plaud]» (60 сек).
  Никакого оптимистичного скрытия по таймеру.
- **Конец звонка** (только если шла запись, запущенная CallCatch, и её
  сессия-владелец завершилась): «✅ Звонок завершён — [Остановить запись] [✕]».
  Автоскрытие 60 сек. Клик: «Останавливаю…» → AX-стоп → успех: «Запись
  остановлена» → скрыть (2 сек); неудача: fallback `plaud://open`.

Одновременно виден один бабл. Новый звонок при видимом бабле конца заменяет
его стартовым баблом — доступ к стопу при этом не теряется: пункт
«Остановить запись» всегда есть в меню (см. ниже).

**4. Menu bar.**
Иконка со статусом: следим / звонок / запись / **«нужно внимание»** (бейдж,
когда нет разрешения Accessibility, не найден user_id или AX-стоп стабильно
падает — с пояснением первым пунктом меню). Меню:
- «Записать сейчас» — активен во время звонка; ручной старт (в т.ч. после
  случайного закрытия бабла).
- «Остановить запись» — активен, пока идёт запись, запущенная CallCatch;
  тот же AX-стоп/fallback, что и кнопка в бабле.
- «Авто-запись: вкл/выкл» — при вкл. запись стартует сама через 7 сек после
  начала звонка, если микрофон всё ещё занят. **Известное ограничение:
  порог отсекает только использования микрофона короче 7 сек; голосовое
  сообщение длиннее 7 сек авто-режим запишет.** (Это осознанный компромисс —
  пользователь включает авто-режим сам.)
- «Запускать при входе» (SMAppService).
- «Выход».

### Поток данных

```
MicMonitor: Discord держит микрофон
  → callStarted(discord), сессия A
    → авто-режим выкл: бабл старта (кнопка «Записать»)
      → клик → PlaudController.startRecording() → pending
    → авто-режим вкл: через 7 сек (мик всё ещё занят) → startRecording()
  → pending: deep link (+повторы при холодном старте Plaud)
  → лог Plaud: success → confirmed, флаг записи = сессия A, бабл «Запись начата»
             : rejected/таймаут → failed, бабл «Запись не началась»
MicMonitor: микрофон Discord свободен ≥5 сек
  → callEnded(discord), сессия A закрыта
    → запись сессии A подтверждена → бабл конца (кнопка «Остановить запись»)
      → клик → AXManualAccessibility → AX-стоп; fallback: plaud://open
    → запись не запускалась → скрыть бабл старта, отменить авто-таймер
```

### Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Plaud не запущен | Deep link запускает его; повторы с backoff до 60 сек; бабл «Запускаю Plaud…» до подтверждения по логу |
| Plaud тихо отказал (профиль не загружен / recorder unavailable / workspace) | В логе `recording_start_rejected` → бабл «⚠️ Запись не началась — [Открыть Plaud]» |
| Plaud уже пишет (запись не наша) | Deep link игнорируется Plaud'ом; флаг не ставим, стоп не предлагаем |
| Подтверждение не пришло за 60 сек | Считаем `failed`, бабл ошибки |
| `user_id` не найден в логах | Иконка «нужно внимание»; настройки: инструкция (Record на web.plaud.ai → «Найти снова») или ручной ввод |
| `user_id` не совпал | Plaud покажет своё уведомление; у нас — бабл ошибки по `recording_start_rejected` |
| AX-дерево Plaud пустое | Выставить `AXManualAccessibility` и повторить; иначе fallback |
| AX-стоп не нашёл кнопку ни в одной из 3 поверхностей | Fallback: `plaud://open` |
| Нет разрешения Accessibility | Системный промпт; иконка «нужно внимание» |

### Сборка

SwiftPM executable target + скрипт сборки `.app`-бандла (Info.plist с
`LSUIElement=true`, `LSMinimumSystemVersion=14.4`). Ad-hoc подпись бандла
(`codesign -s -`): без неё SMAppService может отказать в регистрации
login item. Без нотаризации — личное использование.

**Порядок реализации:** первым шагом — живой пробник интеграции
(деталь для плана): проверить deep link старт (тёплый и холодный),
подтверждение по логу, AX-обход с `AXManualAccessibility`, поведение
CoreAudio Process API для helper-процессов на этой машине. Основную
разработку вести только после зелёного пробника.

### Тестирование

- Юнит-тесты: конечный автомат сессий и записи (звонок→pending→confirmed→
  конец; отказ; таймаут; ложный `callEnded` при mute → unmute → повторный
  `callStarted` не рассинхронизирует флаг) с замоканными
  MicMonitor/PlaudController (протоколы + DI). Дебаунсы — на мок-таймерах.
- Ручная интеграция: реальный звонок в каждом из 4 приложений, **для Telegram —
  оба варианта (нативный и Desktop)**; deep link старт при запущенном и
  незапущенном Plaud; AX-стоп (с включением `AXManualAccessibility`);
  «mute дольше 5 сек» в каждом приложении (не должно давать ложный конец
  звонка; если приложение отпускает микрофон при mute — зафиксировать и
  поднять дебаунс); голосовое сообщение в Telegram при вкл. авто-режиме:
  короче 7 сек — запись не стартует; длиннее 7 сек — стартует (известное
  ограничение, проверяем что бабл корректно показывает состояние).

### Вне скоупа

- Расширяемый пользователем список приложений (зашиты 4 приложения /
  5 bundle-префиксов).
- Программный стоп без Accessibility (в Plaud его не существует).
- Запись звука самим CallCatch — запись всегда делает Plaud.
- Нотаризация, автообновления.
- Подавление авто-записи для длинных (>7 сек) голосовых сообщений.

### Известные риски

- Обновление Plaud может поменять: структуру окон записи (сломается AX-стоп —
  fallback останется), формат/наличие строк лога (сломается подтверждение
  старта — деградация в оптимистичный режим с предупреждением), тонкую
  семантику ветки `auto=1` (недокументированное поведение). Deep link как
  механизм — публичная интеграция Plaud с вебом, риск его исчезновения низкий,
  но семантика тихих отказов может дрейфовать.
- Все проверки кода сделаны на Plaud v1.3.7.
- CoreAudio Process API: если приложение держит микрофон вне звонка —
  будет ложный бабл; допустимо. Поведение helper-процессов (пустой bundle id)
  закрыто fallback'ом через PID.
- SMAppService с неподписанным бандлом может не зарегистрировать автозапуск —
  закрыто ad-hoc подписью в сборке.
