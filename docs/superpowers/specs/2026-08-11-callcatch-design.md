# CallCatch — детект звонков и запись через Plaud

**Дата:** 2026-08-11
**Статус:** дизайн утверждён

## Проблема

Приложение Plaud (десктоп, macOS) умеет авто-детектить звонки только для жёстко
зашитого списка приложений (zoom, teams, slack, webex, lark, браузеры).
Discord и WhatsApp его нативный монитор распознаёт, но отфильтровывает;
Telegram и Signal не распознаёт вообще. Правкой конфига это не расширяется
(список `supportMeetingAppKeysGlobal` зашит в код, `autoRecordApps` фильтруется
по нему).

Нужно: при начале звонка в Discord / Signal / Telegram / WhatsApp показывать
бабл внизу экрана с кнопкой «запустить запись», которая стартует запись в Plaud.

## Ключевые факты о Plaud (проверено по коду v1.3.7)

- Electron-приложение, bundle id `ai.plaud.desktop.plaud`.
- **Старт записи программно:** deep link `plaud://record?auto=1&user_id=<id>`
  (механизм, которым пользуется web.plaud.ai). Проверки на стороне Plaud:
  запись не идёт; `user_id` совпадает с id или id_hash залогиненного
  пользователя. При несовпадении Plaud показывает своё уведомление об ошибке.
  Если запись уже идёт — запрос молча игнорируется.
- `user_id` присутствует в локальных логах Plaud
  (`~/Library/Application Support/Plaud/logs/log-*.log`, поля `userId` /
  `user_id=` в залогированных deep link'ах).
- **Программного стопа нет:** ни deep link, ни локального сервера, ни хоткея,
  ни пункта в tray-меню. Выход из приложения останавливает запись корректно,
  но показывает диалог подтверждения. Единственный путь — Accessibility-клик
  по кнопке стопа в окне/виджете записи Plaud (эквивалент ручного клика,
  штатное сохранение и обработка записи).
- Deep link при незапущенном Plaud сам запускает приложение (стандартное
  поведение URL-схем macOS), старт записи происходит с задержкой на запуск.

## Решение

Нативное menu bar приложение на Swift (AppKit + SwiftUI), без Dock-иконки
(LSUIElement). Рабочее название **CallCatch**.

### Компоненты

**1. MicMonitor — детектор звонков.**
CoreAudio Process Objects API (macOS 14.4+): системные события «процесс
начал/закончил использовать микрофон» (`kAudioHardwarePropertyProcessObjectList`,
`kAudioProcessPropertyIsRunningInput` + property listeners). Событийно, без
поллинга, разрешения не требуются.

Отслеживаемые приложения — фиксированный список, матчинг по **префиксу**
bundle id (звук у Electron-приложений идёт из helper-процессов вида
`<bundle>.helper`):

| Приложение | Префикс bundle id |
|---|---|
| Discord | `com.hnc.Discord` |
| Signal | `org.whispersystems.signal-desktop` |
| Telegram (macOS) | `ru.keepcoder.Telegram` |
| Telegram Desktop | `org.telegram.desktop` |
| WhatsApp | `net.whatsapp.WhatsApp` |

Семантика: «приложение использует микрофон» == «идёт звонок». Ложные
срабатывания (голосовое сообщение в Telegram) допустимы: бабл безвреден,
а авто-режим отсекает их задержкой (ниже).

События наружу: `callStarted(app)`, `callEnded(app)`. Конец звонка — с
дебаунсом 5 сек (переподключение/смена аудиоустройства не считается концом).

**2. PlaudController — управление Plaud.**
- `startRecording()`: открыть `plaud://record?auto=1&user_id=<id>`.
- `user_id`: при первом запуске автоматически извлекается из логов Plaud;
  кэшируется в настройках CallCatch; при неудаче — ручное поле в настройках
  с подсказкой.
- `stopRecording()`: Accessibility API (AXUIElement) — найти окно/виджет
  записи Plaud, найти кнопку стопа, `AXPress`. Требует разрешения
  Accessibility (запрашивается при первом использовании). Fallback при любой
  неудаче: активировать окно Plaud поверх всех — пользователь жмёт стоп сам.
- Знание «идёт ли запись»: внутренний флаг (мы сами инициировали старт) +
  проверка через Accessibility при показе бабла конца. Если состояние
  неопределимо — бабл конца всё равно показываем.

**3. BubbleWindow — бабл.**
Плавающая панель (NSPanel, non-activating, поверх всех окон, все Spaces),
внизу по центру основного экрана. Состояния:

- **Старт звонка:** «📞 Звонок в {приложение} — [Записать в Plaud] [✕]».
  Висит, пока идёт звонок, либо до закрытия. После клика: «Запускаю
  запись…» → скрыть (2 сек). Если Plaud не был запущен: «Запускаю Plaud…».
- **Конец звонка** (только если запись шла): «✅ Звонок завершён —
  [Остановить запись] [✕]». Автоскрытие 60 сек. Кнопка: AX-стоп, при
  неудаче — поднять Plaud.

Одновременно виден один бабл; новый звонок при видимом бабле конца заменяет
его.

**4. Menu bar.**
Иконка со статусом (следим / звонок / запись). Меню:
- «Авто-запись: вкл/выкл» — при вкл. запись стартует сама через 7 сек
  после начала звонка (если микрофон всё ещё занят — отсекает голосовые
  сообщения); бабл в этом случае показывает «Запись начата» без кнопки.
- «Запускать при входе» (SMAppService).
- «Выход».

### Поток данных

```
MicMonitor: Discord держит микрофон
  → callStarted(discord)
    → авто-режим выкл: BubbleWindow (кнопка «Записать»)
      → клик → PlaudController.startRecording() → plaud:// deep link
    → авто-режим вкл: через 7 сек (мик всё ещё занят) → startRecording()
MicMonitor: микрофон свободен ≥5 сек
  → callEnded(discord)
    → запись шла → BubbleWindow (кнопка «Остановить запись»)
      → клик → AX-клик стопа в Plaud; fallback: поднять окно Plaud
```

### Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Plaud не запущен | Deep link запускает его; бабл «Запускаю Plaud…» |
| Plaud уже пишет | Deep link игнорируется Plaud'ом молча; наш флаг записи ставим только если записи не было |
| `user_id` не найден в логах | Настройки: ручной ввод с инструкцией |
| `user_id` не совпал | Plaud покажет своё уведомление; в настройках — подсказка перечитать логи |
| AX-стоп не нашёл кнопку | Поднять окно Plaud поверх всех |
| Нет разрешения Accessibility | Системный промпт; в меню — статус-подсказка |

### Сборка

SwiftPM executable target + скрипт сборки `.app`-бандла (Info.plist с
`LSUIElement=true`, `LSMinimumSystemVersion=14.4`). Без подписи/нотаризации —
личное использование. Запуск при входе через SMAppService.

### Тестирование

- Юнит-тесты: конечный автомат звонок→бабл→запись→конец с замоканными
  MicMonitor/PlaudController (протоколы + DI). Дебаунсы — на мок-таймерах.
- Ручная интеграция: реальный звонок в каждом из 4 приложений; deep link
  старт; AX-стоп; поведение при незапущенном Plaud; голосовое сообщение
  в Telegram при вкл. авто-режиме (не должно стартовать запись).

### Вне скоупа

- Расширяемый пользователем список приложений (зашиты 4).
- Программный стоп без Accessibility (в Plaud его не существует).
- Запись звука самим CallCatch — запись всегда делает Plaud.
- Подпись, нотаризация, автообновления.

### Известные риски

- Обновление Plaud может поменять структуру окна записи — сломается AX-стоп
  (fallback останется рабочим). Deep link — публичный механизм веб-интеграции
  Plaud, риск поломки низкий.
- CoreAudio Process API отдаёт события по процессам: если приложение держит
  микрофон вне звонка (Discord с включённым voice activity вне канала —
  не наблюдалось, но возможно) — будет ложный бабл; допустимо.
